# インポートとエクスポート

*[English](import-export.md) | 日本語*

図の入出力は、ツールバーの「取込」「出力」ボタンから行います。
実データベースからの取込だけは別ボタン「DB取込」です（[データベース連携](database.ja.md)を参照してください）。

| 形式 | インポート | エクスポート |
|---|:-:|:-:|
| 実データベース（5 方言） | ✅ | —（差分同期・DDL で書き戻し） |
| C# コード（生成物 .g.cs） | ✅ | —（コード生成で書き出し） |
| SQL DDL | — | ✅ |
| DBML | ✅ | ✅ |
| Mermaid（erDiagram） | ✅ | ✅ |
| Excel 定義書 | ✅ | ✅ |
| HTML 定義書 | — | ✅ |
| スキーマ JSON（配置情報なし） | — | ✅ |
| PNG / SVG | — | ✅ |
| 印刷 / PDF | — | ✅ |

## インポート

「取込」ボタンからファイルを選ぶと、取込内容が図に反映されます。
DBML と Mermaid は図全体を置き換え、取込後に自動整列が適用されます。
**Excel 定義書はマージ取込**で、一致したテーブル・列は現在の図にある要素をそのまま引き継ぎます。
そのため名前付きクエリ定義や手で配置したレイアウトが温存され、自動整列も行われません。
置換前の確認は無条件ではなく、現在の図が空の場合や、取り込む内容と構造が同一の場合は、確認なしで続行します。

### DBML（.dbml）

`Table` ブロックと `Ref:` 行からなる DBML を取り込みます。
対応範囲は QuickER の DBML エクスポートが書き出すサブセットで、構文だけでなく関係の列対応も往復します（`Ref:` 行に書かれた列名をそのまま端点として使うため、ファイルが名指しした列がそのまま結ばれます）。

- 列設定: `pk` / `ref` / `unique` / `null` / `not null` / `note: '...'`
- テーブルの説明: `Table` ブロック内の `Note: '...'` 行（DBML 標準の書き方。他ツールが書いたファイルからも説明を復元します）
- 一意制約: 列設定の `unique`（その 1 列の制約）と、`Indexes` ブロックの `unique` 索引（`(列, …) [unique, name: '…']`＝複合・名前付き）。
  `unique` でない索引は読み飛ばします
- 関係: `Ref:` 行の `-`（1 対 1）、`<`（1 対 多）、`<>`（多 対 多）。`>`（多 対 1）は未対応。
  端点は単一列（`Parent.a`）と複合 Ref 構文（`Parent.(a, b)`）の両方に対応し、複合外部キーは構成ペアが順序どおりに復元されます。
  両端の列数が食い違う行や、テーブルに無い列名を含む行は、リレーション自体は残したうえで列対応だけを捨てます（プロパティパネルで補えます）
- 制約名と参照アクション: `Ref:` 直後の設定ブロック（`[note: '制約名', delete: cascade, update: set null]`）から復元します。
  DBML の `restrict` は QuickER に対応する値が無いため `NO ACTION` として取り込みます
- 未対応: `Project` / `Enum` / `TableGroup` / 複数行 `Note` ブロック

列を持たないテーブルには既定の PK 列（`ID int`）が補われます。
DBML は方言情報を持たないため、図の対象 DB は取込前のまま維持されます。

### Mermaid（.mmd / .mermaid）

`erDiagram` 記法を取り込みます。
DBML と同じく方言情報を持たないため、対象 DB は維持されます。
キー標識 `UK` は、その 1 列だけの一意制約として取り込みます（Mermaid には複数列をまとめる構文が無いため、複合の一意制約は表現できません）。

### Excel 定義書（.xlsx）

QuickER がエクスポートした定義書を再取込できます。
キー欄の `UQ{n}` は同じ番号が同じ一意制約を表すため、同番の列をまとめて 1 件の制約として復元します（制約名は定義書に載らないため未設定＝DDL 生成時に合成されます）。
シートの役割は非表示の定義タグで判定するため、シート名を変更・翻訳しても取り込めます。
ただし、**他のアプリで作成した Excel は直接取り込めません**（手元の定義書資産を移行する場合は、いったん QuickER の定義書形式に転記してください）。
定義書には対象 DBMS が埋め込まれており、取込時に方言ごと復元されます。
件数の不一致や重複、未定義のテーブル参照は取込エラーになります。

取込側に規模の上限はなく、2 つの役割シート以外のワークシートはすべてテーブル詳細シートとして読み、行は最初の空行まで走査します。
処理は UI スレッドで実行されるため、極端に大きなブックでは終わるまでウィンドウが応答せず、中断する手段もありません。

### C# コード（.cs）

コード生成ツールバーの「コード取込」ボタンから、QuickER が **`IncludeDataAnnotations` ON で生成した、エンティティを含む `.g.cs`**（分割出力・層別出力では `Entities.g.cs`、非分割ではその出力ファイル）を選びます。
取込は Roslyn の構文解析のみ（コンパイル・アセンブリ読込なし）で図を復元し、現在の図へマージします。
対象は `[Table]` を持つクラスだけで、Repository・EditModel・Mapper などのインフラクラスには `[Table]` が付かず、手書き POCO も無視されます（対象クラスが 0 件のときは、エンティティを含む `.g.cs` を選ぶよう案内するエラーになります）。

復元元は次のとおりです。

- **テーブル名**：`[Table]`
- **列名**：`[Column]`
- **列の型と説明**：`[DbColumnMeta]`
- **テーブルの説明**：`[DbTableMeta]`
- **主キー**：`[Key]`
- **NULL 可否**：プロパティ型が `?` かどうか（`[Required]` は一切使いません）
- **UNIQUE 制約**：クラスレベルの `[UniqueConstraint]`
- **リレーション**：`[NavigationReference]`

**失われるもの・変わるものはすべて警告として通知します**（取込完了時に内訳を表示）。
`[DbColumnMeta]` の付いていない列プロパティはスキップされ、それが主キー列のときは「テーブルが主キーを失う」ことまで伝える専用の警告になります。
列を 1 つも復元できなかったテーブルは、落とさずに **列ゼロのテーブル**として取り込みます（落とすと、そのテーブルを端点に持つリレーションまで道連れで消えるため）。
端点の列を解決できなかったリレーションは **列ペアなし**で復元し（DDL 生成・スキーマ差分の対象外になります）、名指しで警告します。
端点のテーブルがファイルに無いリレーション、引数を読み取れない `[NavigationReference]`（引数不足・文字列リテラルでない・`name:` 形式で並びが違う）も同様に名指しで警告します。
同名のテーブル・同名の列はそのまま受け入れたうえで通知します。
1 つのクラスが**同一ファイル内で**複数の `partial` 宣言に分かれている場合は `[Table]` を持つ部分だけを読むため、他の部分に残った列プロパティの件数を通知します（`[Table]` を持つ部分へ移してください）。

**UNIQUE 制約と FK メタデータも往復します。**
制約は `[UniqueConstraint("PropA", "PropB", Name = "UQ_...")]` の各プロパティ名を `[Column]` へ逆写像して復元し、構成列の並びは宣言順、`Name` が無ければ「DDL 生成時に合成」を意味します。
復元できない列を参照する制約（構成 0 件の制約も同様）は、別の意味の制約へ縮めないよう **制約ごと** スキップし、警告で通知します。
FK 制約名と参照アクションは `[NavigationReference]` の名前付き引数 `ConstraintName` / `OnDelete` / `OnUpdate` から復元します（既定値と異なるときだけ出力され、解釈できないアクションのトークンは警告のうえ未指定として扱われます）。

列型は方言中立トークンから、現在の図が使う方言のネイティブ型へ展開します（展開できないトークンは警告のうえそのまま採用）。
トークンは型の「意味」だけを運ぶため、同じ意味の複数表記（`numeric` と `decimal`・`ntext` と `nvarchar(max)`・`datetime` と `datetime2`）は 1 つの代表表記へ畳まれます。
そこで、綴りが変わってしまう列についてはコード生成が元の表記も `[DbColumnMeta]` へ記録し（`NativeType`）、対象の列を情報診断で名指しします。
取込側は、記録された表記を現在の方言で解析した型がトークンと一致するときだけそれを採用するため、**`datetime` 列は `datetime` のまま戻ります**（`datetime2` へ化けて次の DB 同期が `ALTER COLUMN` を出す、ということが起きません）。
手編集や別方言向けの生成物で両者が食い違うときは、トークン側を採って警告します。
**コードは方言中立のため、取込後も図の対象 DB は取込前のまま維持されます**。

多対多リレーションはコードに存在しないため、既存図へのマージ取込では両端が生存する多対多を現在図から温存します（コードで消えた通常のリレーションは図からも消えます）。
FK メタデータの温存は **未指定分だけの fallback** で、端点（両端テーブル名・列名）が一致するリレーションについて、コードが指定していないフィールドだけを現在図から補完します（指定があればコードが勝ちます）。
旧バージョンで生成したコード（名前付き引数を持たない）も、この規則で全フィールドが未指定＝現在図の値がそのまま温存されます。
一方で **UNIQUE 制約はコードが正本** で、現在図からの温存は行いません（属性が無いことは「制約を持たないテーブル」と区別できず、温存するとコード上で削除した制約を消せなくなるため）。
他の取込と同様、構造差分や壊れる名前付きクエリがあるときは置換確認が出ます。

**コードが語れないもの。**
複合主キー自身の列順序はコードに載りません。
`[Key]` はプロパティの宣言位置（＝図の列順）に付くだけなので、複合キーの順序が列順と食い違う図は、キーが列順に戻った形で取り込まれます。
複数行の説明は、コード生成の時点で空白へ畳まれます（`///` の summary と属性のリテラルに改行を載せられないため）。
取込は畳まれた文面をそのまま復元するので、元の改行は戻りません。
FK 制約名と参照アクションは既定値と異なるときだけ出力されるため、「名前なし・両方 `NO ACTION`」は「未指定」と区別できません。
マージ取込ではそれらのフィールドに現在図の値がそのまま残り、CLI のリバースでは既定値になります。
`record` 宣言のエンティティは解析対象外です（生成エンティティは常に `class`）。
また `[Table]` の `Schema` 引数は読みません（生成側が出力せず、スキーマ修飾はテーブル名自体に含まれるため）。

CLI の `quicker reverse` は、同じ解析でマージなしの新規図（スキーマのみ JSON）を書き出し、`--out` の親ディレクトリが無ければ作成します（[CLI リファレンス](cli.ja.md) を参照）。

## エクスポート

「出力」ボタンから形式を選びます。

### SQL DDL（.sql）

図の対象 DBMS の方言で CREATE 文一式を出力します。

### DBML / Mermaid

テキスト形式へ書き出します。
DBML の出力は上記インポートと同じサブセット（`Table` ブロック＋ `Ref:` 行）で、書き出したファイルは関係の列対応を保ったまま再取込できます。
複合外部キーは DBML 標準の複合 Ref 構文（`Ref: Parent.(a, b) < Child.(x, y)`）で書き出します（単一列の外部キーは従来どおり `Parent.a < Child.x` 形式のまま）。
一意制約は、名前なしの単一列制約を列設定 `unique` として、複合制約と名前付き制約を `Indexes` ブロック（`(列, …) [unique, name: '…']`）として書き出します。
Mermaid はキー欄が 1 列 1 標識のため `PK` > `FK` > `UK` の優先度で 1 つに畳み、**`UK` を出力するのは単一列制約の構成列だけ**です（複合制約を列ごとに分解すると、取込時に「単一列制約 × N」という別の意味になるため出力しません）。

どちらも dbdiagram.org などの DBML 対応ツールや、Mermaid を表示できる GitHub / ドキュメントツールとの連携に使えます。
ただし複合主キー自身の列順序はどちらの形式も表現できず（キー列それぞれに `pk` / `PK` の標識が付くだけ）、順序が列順と食い違うキーは再取込で列順に戻ります。

DBML はテーブルの説明を `Note:` 行、外部キーの参照アクションを `Ref:` 行の設定ブロック（`delete` / `update`。既定の `NO ACTION` は書きません）としても出力するため、これらも往復します。

出力形式が構造的に表現できない情報は、出力完了のダイアログに内訳が出ます（うるさくならないよう、同じ形式ではセッション中 1 回だけ）。
Mermaid は説明・メモ・NULL 許可・複合 UNIQUE 制約・UNIQUE 制約名・外部キーの列対応・参照アクション・名前付きクエリを表現できないため、図にそれらが入っていれば告知されます。
DBML で告知されるのはテーブルのメモと名前付きクエリだけです（`Note` は説明に使うため、メモを載せるには独自拡張が必要になり、他ツールとの交換を優先して見送っています）。
SQL DDL や定義書は「その形式では出さないのが正しいもの」しか落ちないため、告知しません。

### Excel 定義書（.xlsx）

テーブル一覧、リレーション一覧、テーブル別の詳細シート（列の型・必須・キー・説明）からなる定義書を出力します。
キー欄は `PK` / `FK{n}` に加えて一意制約を `UQ{n}`（`PK/UQ1` や `FK1/UQ2` のような併記あり）で表します。
`PK` に序数は付かないため、複合主キー自身の列順序はこの定義書にも載りません（再取込では列順に戻ります）。
`n` は制約の登場順で、**同じ番号は同じ制約**を意味するため、複合制約は構成列すべてに同じ番号が並びます（複合外部キーの `FK{n}` も同じ流儀です）。

リレーション一覧は 1 行 1 リレーションを保ち、複合外部キーは参照元列・参照先列のセルへ構成列を宣言順のカンマ区切りで並べます（`TenantRef, RegionRef` / `TenantId, RegionCode`）。
再取込時はこれを分割して列ペアへ戻します（両側の列数は一致している必要があります）。
対象 DBMS がファイルに埋め込まれるため、この定義書は QuickER への再取込で図に戻せます。

セルはすべて値（テキスト）として書き出し、QuickER が数式を書くことはありません。
そのため `=` で始まるテーブル名・列名もブック内では文字列のままで、Excel で開いても評価されません。
QuickER に CSV 出力はありませんが、定義書を自分で CSV へ変換する場合は注意が要ります。
表計算ソフトは CSV を開くときに先頭の `=` / `+` / `-` / `@` を数式の始まりとして読むため、変換時に引用符で囲んでください。

### HTML 定義書（.html）

外部参照も JavaScript も含まない自己完結の単一 HTML を出力します。
中身は次のとおりです。

- サイドバーのナビゲーション
- 概要（対象 DBMS・テーブル数・リレーション数）
- テーブル一覧
- リレーション一覧（ON DELETE / ON UPDATE を含む）
- テーブル別詳細

ブラウザだけで閲覧できるため、開発者以外の関係者への配布に向きます。

図を修正したら定義書を再出力するだけで最新化できます。
再出力を手順に組み込んでおけば、「ドキュメントだけ古い」状態を避けやすくなります。

### スキーマ JSON（.json）

図の保存形式（[ER 図の編集](er-editor.ja.md) を参照）から配置情報（座標・色などの layout）を除いた、スキーマ定義と名前付きクエリ定義だけの JSON を出力します（`{ "Version": 1, "Schema": { ... } }`。キーは大文字始まりで、大文字小文字を区別します）。
配置情報を持たないため差分が安定し、テーブル定義そのものをレビュー・バージョン管理したいときに向きます。
このファイルは QuickER で「開く」と読み込め、配置情報がないため全体が自動整列されます（スキーマと名前付きクエリ定義については可逆ですが、座標・色は復元されません）。
通常保存（layout 込みの `.json`）とは別に、配置の揺れを含めずスキーマだけを共有したい場合に使います。

### PNG / SVG（画像）

図全体を画像として出力します。
どちらの形式も画面のズーム倍率の影響は受けません。
SVG は図のモデルから直接描くため選択枠や方眼背景を含みません。
PNG はキャンバスの描画をそのまま写すため、選択状態（選択枠や関連ハイライトによる減光）と方眼背景も反映されます。
PNG を出力する前には選択を解除しておいてください。

SVG に載る名前・説明はすべて XML エスケープされるため、図に書いた内容がマークアップを破ることはありません。
例外は名前に含まれる制御文字で、これはそのまま書き出されます。
XML は本文中の制御文字を認めないため、ファイル自体は何事もなく書き出されたうえで、どの SVG ビューアでも開けません。
出力時にそうした名前を弾く仕組みはないので（名前の制御文字を検査する入口は DDL 生成とコード生成であって、エクスポートではありません）、名前の側に制御文字を入れないでください。

### 印刷 / PDF

ツールバーの「印刷」（Ctrl+P）で印刷オプションダイアログが開きます。

- **図のタイトル**：ヘッダに印字するタイトル
- **印刷サイズ**：「用紙 1 ページに縮小して印刷」（既定）/「原寸大で印刷」（用紙サイズを図の実寸に合わせる・PDF 出力向け）
- **印刷日時をヘッダに印字する**：既定 ON

Microsoft Print to PDF などの PDF プリンタを選べば、そのまま PDF 出力になります。
