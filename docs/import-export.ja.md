# インポートとエクスポート

*[English](import-export.md) | 日本語*

図の入出力は、ツールバーの「取込」「出力」ボタンから行います（実データベースからの取込は別ボタン「DB取込」です。[データベース連携](database.ja.md)を参照してください）。

| 形式 | インポート | エクスポート |
|---|:-:|:-:|
| 実データベース（5 方言） | ✅ | —（差分同期・DDL で書き戻し） |
| C# コード（生成物 .g.cs） | ✅ | —（コード生成で書き出し） |
| SQL DDL | — | ✅ |
| DBML | ✅ | ✅ |
| Mermaid（erDiagram） | ✅ | ✅ |
| Excel 定義書 | ✅ | ✅ |
| HTML 定義書 | — | ✅ |
| スキーマ JSON（配置情報なし） | — | ✅ |
| PNG / SVG | — | ✅ |
| 印刷 / PDF | — | ✅ |

## インポート

「取込」ボタンからファイルを選ぶと、取込内容が図に反映されます。DBML と Mermaid は図全体を置き換え、取込後に自動整列が適用されます。**Excel 定義書はマージ取込**で、一致したテーブル・列が現在の図の要素の同一性を引き継ぐため、名前付きクエリ定義や手で配置したレイアウトが温存され、自動整列も行われません。置換前の確認は無条件ではなく、現在の図が空の場合や、取り込む内容と構造が同一の場合は、確認なしで続行します。

### DBML（.dbml）

`Table` ブロックと `Ref:` 行からなる DBML を取り込みます。対応範囲は QuickER の DBML エクスポートが書き出すサブセットで、構文だけでなく関係の列対応も往復します（`Ref:` 行に書かれた列名をそのまま端点として使うため、ファイルが名指しした列がそのまま結ばれます）。

- 列設定: `pk` / `ref` / `unique` / `null` / `not null` / `note: '...'`
- 一意制約: 列設定の `unique`（その 1 列の制約）と、`Indexes` ブロックの `unique` 索引（`(列, …) [unique, name: '…']`＝複合・名前付き）。`unique` でない索引は読み飛ばします
- 関係: `Ref:` 行の `-`（1 対 1）、`<`（1 対 多）、`<>`（多 対 多）。`>`（多 対 1）は未対応。端点は単一列（`Parent.a`）と複合 Ref 構文（`Parent.(a, b)`）の両方に対応し、複合外部キーは構成ペアが順序どおりに復元されます。両端の列数が食い違う行や、テーブルに無い列名を含む行は、リレーション自体は残したうえで列対応だけを捨てます（プロパティパネルで補えます）
- 未対応: `Project` / `Enum` / `TableGroup` / 複数行 `Note` ブロック

列を持たないテーブルには既定の PK 列（`ID int`）が補われます。DBML は方言情報を持たないため、図の対象 DB は取込前のまま維持されます。

### Mermaid（.mmd / .mermaid）

`erDiagram` 記法を取り込みます。DBML と同じく方言情報を持たないため、対象 DB は維持されます。キー標識 `UK` は、その 1 列だけの一意制約として取り込みます（Mermaid には複数列をまとめる構文が無いため、複合の一意制約は表現できません）。

### Excel 定義書（.xlsx）

QuickER がエクスポートした定義書を再取込できます。キー欄の `UQ{n}` は同じ番号が同じ一意制約を表すため、同番の列をまとめて 1 件の制約として復元します（制約名は定義書に載らないため未設定＝DDL 生成時に合成されます）。シートの役割は非表示の定義タグで判定するため、シート名を変更・翻訳しても取り込めますが、**他のアプリで作成した Excel を直接取り込むことはできません**（手元の定義書資産を移行する場合は、いったん QuickER の定義書形式に転記してください）。定義書には対象 DBMS が埋め込まれており、取込時に方言ごと復元されます。件数の不一致や重複、未定義のテーブル参照は取込エラーになります。

### C# コード（.cs）

コード生成ツールバーの「コード取込」ボタンから、QuickER が **`IncludeDataAnnotations` ON で生成した本体 `.g.cs`** を選ぶと、Roslyn の構文解析のみ（コンパイル・アセンブリ読込なし）で図を復元し、現在の図へマージ取込します。`[Table]` を持ち、**かつ** `[DbColumnMeta]` の付いた列プロパティを 1 つ以上持つクラスだけが対象で、Repository などのインフラクラスや手書き POCO は無視されます（対象クラスが 0 件のときは、生成物の本体 `.g.cs` を選ぶよう案内するエラーになります）。テーブル名は `[Table]`、列名は `[Column]`、列の型と説明は `[DbColumnMeta]`、テーブルの説明は `[DbTableMeta]`、主キーは `[Key]`、NULL 可否はプロパティ型が `?` かどうか（`[Required]` は一切使いません）、リレーションは `[NavigationReference]` から復元します。`[DbColumnMeta]` の付いていない列プロパティは、警告のうえスキップされます。

列型は方言中立トークンから現在の図の方言のネイティブ型へ展開します（展開できないトークンは警告のうえそのまま採用）。**コードは方言中立のため、取込後も図の対象 DB は取込前のまま維持されます**。多対多リレーション・`ON DELETE` / `ON UPDATE`・FK 制約名はコードに存在しないため、既存図へのマージ取込では、端点（両端テーブル名・列名）が一致するリレーションの参照アクション・制約名と、両端が生存する多対多リレーションを現在図から温存します（コードで消えた通常のリレーションは図からも消えます）。他の取込と同様、構造差分や壊れる名前付きクエリがあるときは置換確認が出ます。

CLI の `quicker reverse` は、同じ解析でマージなしの新規図（スキーマのみ JSON）を書き出します（[CLI リファレンス](cli.ja.md) を参照）。

## エクスポート

「出力」ボタンから形式を選びます。

### SQL DDL（.sql）

図の対象 DBMS の方言で CREATE 文一式を出力します。

### DBML / Mermaid

テキスト形式へ書き出します。DBML の出力は上記インポートと同じサブセット（`Table` ブロック＋ `Ref:` 行）で、書き出したファイルは関係の列対応を保ったまま再取込できます。複合外部キーは DBML 標準の複合 Ref 構文（`Ref: Parent.(a, b) < Child.(x, y)`）で書き出します（単一列の外部キーは従来どおり `Parent.a < Child.x` 形式のまま）。一意制約は、名前なしの単一列制約を列設定 `unique` として、複合制約と名前付き制約を `Indexes` ブロック（`(列, …) [unique, name: '…']`）として書き出します。Mermaid はキー欄が 1 列 1 標識のため `PK` > `FK` > `UK` の優先度で 1 つに畳み、**`UK` を出力するのは単一列制約の構成列だけ**です（複合制約を列ごとに分解すると、取込時に「単一列制約 × N」という別の意味になるため出力しません）。dbdiagram.org などの DBML 対応ツールや、Mermaid を表示できる GitHub / ドキュメントツールとの連携に使えます。

### Excel 定義書（.xlsx）

テーブル一覧、リレーション一覧、テーブル別の詳細シート（列の型・必須・キー・説明）からなる定義書を出力します。キー欄は `PK` / `FK{n}` に加えて一意制約を `UQ{n}`（`PK/UQ1` や `FK1/UQ2` のような併記あり）で表します。`n` は制約の登場順で、**同じ番号は同じ制約**を意味するため、複合制約は構成列すべてに同じ番号が並びます（複合外部キーの `FK{n}` も同じ流儀です）。リレーション一覧は 1 行 1 リレーションを保ち、複合外部キーは参照元列・参照先列のセルへ構成列を宣言順のカンマ区切りで並べます（`TenantRef, RegionRef` / `TenantId, RegionCode`）。再取込時はこれを分割して列ペアへ戻します（両側の列数は一致している必要があります）。対象 DBMS がファイルに埋め込まれるため、この定義書は QuickER への再取込で図に戻せます。

### HTML 定義書（.html）

外部参照も JavaScript も含まない自己完結の単一 HTML を出力します。サイドバーのナビゲーション、概要（対象 DBMS・テーブル数・リレーション数）、テーブル一覧、リレーション一覧（ON DELETE / ON UPDATE を含む）、テーブル別詳細で構成され、ブラウザだけで閲覧できるため、開発者以外の関係者への配布に向きます。

図を修正したら定義書を再出力するだけで最新化できるので、再出力を手順に組み込んでおけば「ドキュメントだけ古い」状態を避けやすくなります。

### スキーマ JSON（.json）

図の保存形式（[ER 図の編集](er-editor.ja.md) を参照）から配置情報（座標・色などの layout）を除いた、スキーマ定義と名前付きクエリ定義だけの JSON（`{ "Version": 1, "Schema": { ... } }`。キーは大文字始まりで、大文字小文字を区別します）を出力します。配置情報を持たないため差分が安定し、テーブル定義そのものをレビュー・バージョン管理したいときに向きます。このファイルは QuickER で「開く」と読み込め、配置情報がないため全体が自動整列されます（スキーマと名前付きクエリ定義については可逆ですが、座標・色は復元されません）。通常保存（layout 込みの `.json`）とは別に、配置の揺れを含めずスキーマだけを共有したい場合に使います。

### PNG / SVG（画像）

図全体を画像として出力します。どちらの形式も画面のズーム倍率の影響は受けません。SVG は図のモデルから直接描くため選択枠や方眼背景を含みませんが、PNG はキャンバスの描画をそのまま写すため、選択状態（選択枠や関連ハイライトによる減光）と方眼背景も反映されます。PNG を出力する前には選択を解除しておくことをおすすめします。

### 印刷 / PDF

ツールバーの「印刷」（Ctrl+P）で印刷オプションダイアログが開きます。

- **図のタイトル** — ヘッダに印字するタイトル
- **印刷サイズ** — 「用紙 1 ページに縮小して印刷」（既定）/「原寸大で印刷」（用紙サイズを図の実寸に合わせる・PDF 出力向け）
- **印刷日時をヘッダに印字する**（既定 ON）

Microsoft Print to PDF などの PDF プリンタを選べば、そのまま PDF 出力になります。
