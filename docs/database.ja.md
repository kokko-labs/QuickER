# データベース連携

*[English](database.md) | 日本語*

QuickER は、稼働中のデータベースからスキーマを取り込んで図に起こし、図とデータベースの差分を検出して同期スクリプトを適用し、図から DDL を生成します。図とデータベースをどちらの向きにも往復できるため、図が現実から置き去りになりません。

## 対応 DBMS

| DBMS | スキーマ取込 | 差分同期 | DDL 生成 | 方言切替 | 備考 |
|---|:-:|:-:|:-:|:-:|---|
| SQL Server | ✅ | ✅ | ✅ | ✅ | 説明は拡張プロパティ（MS_Description）と同期 |
| PostgreSQL | ✅ | ✅ | ✅ | ✅ | 13 以降 |
| MySQL | ✅ | ✅ | ✅ | ✅ | 8.0 以降（MariaDB は対象外） |
| Oracle | ✅ | ✅ | ✅ | ✅ | 19c 以降 |
| SQLite | ✅ | ✅ | ✅ | ✅ | ファイル DB。差分同期はテーブル再構築方式 |

実データベースを使う取込・同期は、実 DB 統合テスト（SQL Server / PostgreSQL / MySQL / Oracle は Testcontainers の実コンテナ、SQLite は実ファイル DB）で継続的に検証しています。

## スキーマ取込（DB → 図）

ツールバーの「DB取込」ボタンから、接続ダイアログ「データベースから取込」を開きます。

### 接続の指定

- **サーバー型 DBMS** — 対象 DB、ホスト、ポート（空欄で方言の既定値）、データベース名、ユーザー名、パスワードを指定します。SQL Server では認証方式（Windows 認証 / SQL Server 認証）と「サーバー証明書を信頼する (TrustServerCertificate)」も選べます。Oracle にはサービス名の欄があります
- **SQLite** — ファイルパスを「参照...」から指定します（取込のため、既存ファイルのみ）
- **接続テスト** — 実際にスキーマの取得を試行し、検出したテーブル数を表示します

### 接続プロファイル

入力内容は名前を付けて保存でき、次回から「保存済み接続」で呼び出せます。プロファイルは `%AppData%\QuickER\connections.json` に保存され、パスワードは本体とは分離した別ファイルへ **Windows DPAPI（CurrentUser スコープ）で暗号化**して保存されます（「保存」チェックを付けた場合のみ。平文では保存されません）。最後に使った接続内容は自動的に記憶され、次回起動時に復元されます。

### 取り込まれる内容

- テーブル（ビューは対象外）と列（型・長さ・精度・NULL 可否）
- 主キー（複合キーの列順序を保持）
- 外部キー（制約名と ON DELETE / ON UPDATE の参照アクションを含む）。参照先が主キーまたは一意制約と一致する場合は 1 対 1 と判定されます
- テーブル・列の説明（SQL Server の MS_Description 拡張プロパティ）

取込結果は図全体を置き換えます。現在の図と構造的な差分がある場合のみ、置換の確認ダイアログが表示されます（空の図や、構造が同一の図への再取込では確認なしで続行します）。取込後は自動整列が適用されます。

取り込んだ後、手元の既存エンティティ資産と生成コードをどう付き合わせるかは、[生成コードの使い方の「既存コードベースとの共存」](code-generation.ja.md#既存コードベースとの共存)を参照してください。

## 差分同期（図 → DB）

ツールバーの「DB同期」ボタンから、差分ダイアログ「DB スキーマ同期 (差分実行)」を開きます。データベースの現状と図の内容を突き合わせ、差分の一覧と生成 SQL のプレビューを確認したうえで、選択した項目だけを実行できます。

### 検出される差分

- テーブルの追加・削除
- 列の追加・変更（型・NULL 可否）・削除
- 外部キーの追加・削除
- テーブル・列の説明の設定・更新・削除
- 列の並び順の変更（同期できるのは SQLite / MySQL）

同名の要素を同一とみなして比較するため、リネームは「削除＋追加」として検出されます。

列の並び順は、追加・削除を除いた共通列の相対順序で比較されます。SQLite と MySQL では選択可能な差分項目（既定では未選択）として同期でき、SQLite はテーブル再構築に畳み込み、MySQL は `ALTER TABLE ... MODIFY ... AFTER` で移動する列を最小限にします。他の 3 方言では案内として表示されるのみで、同期の対象外です。

### 実行の安全設計

- **破壊的な差分（削除・型変更）は既定で選択されず**、実行時には破壊的変更を含む旨の確認が表示されます
- 生成スクリプトは依存関係順（テーブル追加 → 列追加 → 列変更 → FK 削除 → 列削除 → テーブル削除 → FK 追加 → 説明）に並び、種別ごとの見出しコメントが付きます
- FK 列を解決できない外部キー追加は、不正な DDL を出さずスキップコメントとして出力され、差分一覧にもその旨が表示されます
- SQL Server と SQLite ではトランザクションで実行され、失敗時はロールバックされます。MySQL / Oracle は DDL が暗黙コミットされる仕様のため、途中で失敗した場合は部分適用となる可能性がある旨が警告されます
- SQLite の再構築を含む実行では、再構築されるテーブルを列挙した専用の確認が表示されます
- 差分が 1 件もない場合は、その旨を表示してダイアログは自動で閉じます

### 説明の同期（SQL Server）

テーブル・列の説明は MS_Description 拡張プロパティとして同期されます。既存の有無を判定して追加と更新を使い分け、図側で説明を空にすると削除される、冪等な設計です。

### SQLite の差分同期（テーブル再構築方式）

SQLite は `ALTER TABLE` でできる変更が限られているため、列の変更・削除などを含む同期はテーブル再構築方式で行います。「データベースの現状＋選択した差分」を合成した新しい定義のテーブルを作成し、データを移送してから旧テーブルと入れ替え、インデックスなどの補助オブジェクトを再作成します。再構築はトランザクション内で実行され、コミット前に外部キー整合を検査（`PRAGMA foreign_key_check`）して、違反があればロールバックのうえ違反テーブルを報告します。

同期先の SQLite ファイルは、接続ダイアログの「新規作成」ボタンで新しく作ることもできます。空のデータベースへ図全体を適用して、新規構築に使えます。

## 方言切替

ツールバー右の「対象DB:」コンボで、図のターゲット DBMS をいつでも切り替えられます。

- 全列の型は「元方言 → 中立の正規型 → 新方言」の経路で自動変換されます
- 変換できなかった列は元の型を保持したまま、警告ダイアログに一覧表示されます
- 切替と型変換は 1 回の Undo でまとめて戻せます

## DDL 生成

ツールバーの「出力」から SQL DDL を選ぶと、図の対象 DBMS の方言で CREATE 文一式を出力します。テーブル・列の説明も DDL に含まれます（SQL Server は sp_addextendedproperty、PostgreSQL / Oracle は COMMENT ON、MySQL は COMMENT 句、SQLite はコメント行）。エクスポート全般の操作は[インポートとエクスポート](import-export.ja.md)を参照してください。
