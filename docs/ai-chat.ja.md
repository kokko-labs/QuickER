# AI チャットの設定

*[English](ai-chat.md) | 日本語*

ツールバーの「AI チャット」から、対話で ER 図を生成・編集できます（例:「EC サイトの注文管理に必要なテーブルを設計して」「orders に配送先住所を追加して」）。同じ接続設定で、現在の ER 図から Web モック画面を生成する「AI モック生成」も利用できます（下記[AI モック生成](#ai-モック生成)を参照）。

この内蔵チャットは、GUI で現在開いている図を編集します。外部の AI エージェント（Claude Code・Codex など）に、自身のワークフローの一部として QuickER を駆動させたい場合は、[MCP サーバ](mcp.ja.md)を使ってください。

## 接続方式

チャット画面の接続タブは 3 つで、方式としては 5 種を選べます。API キータブ（OpenAI API / Anthropic API / OpenAI 互換のローカル LLM）、Codex タブ、Claude タブです。

### 1. API キー（「API キー接続」タブ）

| プロバイダー | 必要なもの |
|---|---|
| OpenAI | OpenAI の API キー |
| Claude (Anthropic) | Anthropic の API キー |
| Local LLM | OpenAI 互換 API のローカル LLM（Ollama・LM Studio・llama.cpp・vLLM など） |

プロバイダーとモデルを選び、API キーを入力します。「保存」を有効にすると、キーは **Windows DPAPI（CurrentUser スコープ）で暗号化**されてユーザープロファイル配下に保存され、次回起動時に自動入力されます（平文では保存されません。DPAPI の CurrentUser 保護は Windows のユーザーアカウントに紐づくため、保護の強さはそのアカウントの安全性に依存します）。

「Local LLM」では、エンドポイント欄にサーバーの URL を指定します（`/v1` まで含めます。既定は Ollama の `http://localhost:11434/v1`）。API キーは任意で、認証不要のサーバーなら空のまま、認証を課すサーバーなら入力します。選んだプロバイダーとエンドポイントは記憶され、次回起動時に復元されます。

### 2. Codex（「Codex 接続」タブ）

インストール済みの Codex CLI のアカウント認証を利用します（API キー不要）。`config.toml` に定義したプロバイダーも候補に表示されます。

### 3. Claude Code（「Claude 接続」タブ）

インストール済みの Claude Code のアカウント認証を利用します（API キー不要）。モデルはエイリアス（sonnet など）から選択します。

最後に使った接続タブは記憶され、次回起動時に自動選択されます。

## できること

- **図の生成** — 要件を伝えるとテーブル・カラム・リレーションを作成
- **図の編集** — 既存の図に対する追加・変更・削除（テーブル・カラム・リレーションの操作は Undo/Redo 履歴に乗るため元に戻せます。名前付きクエリの更新は履歴を経由せず直接反映されます）
- **添付** — ファイルを添付して、既存の設計資料などを文脈として渡せます。添付できる種別は接続方式によって異なり（OpenAI 互換は画像とテキスト、Anthropic API は画像・PDF・テキスト、Claude Code は画像・PDF・テキストに加えてその他のバイナリにも対応、Codex は添付に非対応）、種別ごとにサイズ上限があります
- **AI モック生成** — 現在の ER 図から Web モック画面を生成し、モックフォルダとして保存（下記参照）

## AI モック生成

「AI モック生成」は、現在の ER 図から Web モック画面を起こします。成果は**モックフォルダ**（`mock.json` マニフェスト＋画面ごとの HTML＋共有 `style.css`）として保存され、会話しながらライブで書き出されます。空フォルダを指定すれば新規に、既存のモックフォルダを指定すれば続きから作れます（会話は新規に始まり、再開は会話履歴ではなくフォルダの内容から復元するため、どのバックエンドでも動作します）。画面一覧サイドバーから画面をクリックで切り替えられ、プレビューは画面間のリンク遷移に追従します。モック全体は自己完結の単一 HTML ファイルとして出力できます。モックフォルダから画面設計書（`README.md`＝画面一覧・Mermaid の遷移図・画面×エンティティの CRUD 表・画面ごとの項目表）を AI を使わず決定的に生成することもできます。一度出力すると、以降は画面の保存・削除に合わせて自動で書き直され、GitHub でフォルダを開くとフォルダのトップに表示されます。AI は画面を保存する際に各画面のエンティティ使用（CRUD）を宣言し、その宣言が画面×エンティティ表として載ります（宣言が 1 件も無ければ表は省略されます）。

任意の第 2 ステップとして、モックフォルダから実行可能な**モックプロジェクト**を 3 バックエンドのいずれでも生成できます。ターゲットを選べます — **Blazor Web App**（既定。グローバルに InteractiveServer で対話動作し、各画面の HTML と共有 `style.css` を可能な限りそのまま移植して web ネイティブに再現します）か **WPF (.NET)**。ソリューション・csproj・データ層コード（Entity / EditModel / Mapper / インメモリ Repository。図の方言が対応していれば QuickER 版 Repository も）は ER モデルから QuickER が決定的に生成するため、AI が書くのは UI 層だけです。モックフォルダは `design/mock/` に同梱され、AI がそれを基に UI を実装します。Claude Code / Codex はエージェントがファイルを編集し `dotnet build` が通るまで（または実行全体の時間上限に達するまで）自己修正します。API キーはモデルが決定的な一発生成でファイルを提出する方式（自己修正なし・ビルド失敗時のみ修正 1 回）のため、失敗することがあります。いずれの場合も、最後は QuickER 自身の `dotnet build` で結果を検証します。追加指示欄から、その実装への追加の指示を渡せます。

この第 2 ステップは PoC・プロトタイピングの補助です。AI のモデルと接続方式によってはビルドエラーが残ることがあり、最終ビルドが失敗した場合も生成物とログは出力フォルダに残るため、手で修正して続行できます。

## 注意

- API キー方式・Codex・Claude Code のいずれも、図の内容（テーブル定義など）が選択した AI プロバイダーへ送信されます。機密性の高いスキーマを扱う場合は、所属組織のポリシーに従ってください
- AI 機能を使わない場合、API キー等の設定は不要です（ER 図デザイナ・コード生成はネットワークに接続せずに動作します）
