# ER 図の編集

*[English](er-editor.md) | 日本語*

QuickER のメイン画面は 3 ペイン構成です。
左が「ツールボックス」（エンティティ・リレーションの作成）、中央がキャンバス、右が「プロパティ」パネル（選択中の要素の編集）で、中央と右の境界はドラッグで広さを変えられます。
要素の編集はダイアログを開かず、選択して右のプロパティパネルで直接行います。
左右のパネルはツールバーのトグル（F9 / F10）で畳めるので、図を広く見たいときは両方隠してキャンバスだけにできます。

## エンティティ

### 作成と削除

ツールボックスの「エンティティ追加」で、新しいテーブルがキャンバスへ追加されます（PK 列 `ID` 付きの `NewTable` として作成され、選択状態になります）。
削除は「エンティティ削除」ボタンか Delete キーで行います。
複数選択中は一括削除になり、接続されたリレーションも一緒に削除されます。
削除したエンティティに定義した名前付きクエリも一緒に削除され、削除を元に戻すとクエリも戻ります。

エンティティはドラッグで移動できます。
Ctrl+C / Ctrl+V のコピー・貼り付け、Ctrl+D（ツールバー「複製」）の複製にも対応しています。

### プロパティの編集

エンティティを選択すると、プロパティパネルで次を編集できます。

| 項目 | 内容 |
|---|---|
| テーブル名 | テーブルの物理名。前後の空白は除かれ、ほかのテーブルと大文字小文字を除いて同じ名前は受け付けません（下の「名前」を参照） |
| 説明 | テーブルの説明。SQLite 以外の DBMS では、データベースの説明と同期します（SQL Server では拡張プロパティの MS_Description。[説明の同期](database.ja.md#説明の同期)を参照） |
| タイトル背景 | カードのタイトル色（ブルー / グリーン / イエロー / パープル / ピンク / グレー） |
| 項目 | 列の一覧（次節） |
| メモ | データベースにも生成コードにも出さない自由記入欄。Excel / HTML 定義書には出力され、Excel 定義書の再取込で復元されます |

### 列の編集

列はプロパティパネルの「項目」グリッドでインライン編集します。

- **追加 / 削除**：グリッド右上の「＋」で列を追加（現在の対象 DB の既定型で作成）、「−」または行末の削除ボタンで削除します
- **編集項目**：PK / FK / NULL のチェック、カラム名、型（対象 DB の型一覧から選択・自由入力も可）、説明
- **並び替え**：行をドラッグして並び順を変更します
- **コピー / 貼り付け**：グリッド上で Ctrl+C / Ctrl+V が列単位で機能します

### 主キーの順序

複合主キーは複数の列に PK チェックを付けて表現します。
どの列を主キーにするかは常に PK チェックボックスが握り、キー自身の列順序はそれとは別に「主キーの順序」カードで編集します。
カードはプロパティパネルのカラム一覧と UNIQUE 制約カードの間に出て、選択中のテーブルの主キー列が 2 本以上のときだけ表示されます。
実効順に 1 列 1 行を並べ、↑ / ↓ で行を移動できます（端の行ではボタンが無効になります）。
この順序が生成される `PRIMARY KEY` 制約と裏付けインデックスの列順そのものです。
1 回の移動が 1 回の Undo 単位になります。

順序を明示するまではグリッドの列の並びに従うので、エディタで作った図では行をドラッグすればキーの順序も追従します。
一度明示すると、順序はそこで固定されます（カードで並べ替える・AI ツールの `set_primary_key` を呼ぶ・データベースから取り込む、のいずれでも）。
以後はグリッドで列を並べ替えてもキーの順序は変わらず、あとから PK チェックを付けた列は主キーの末尾に入ります（固定された順序に元から載っていた列は、以前の位置へ戻ります）。

### 一意制約

プロパティパネルの項目グリッドの下に、テーブルごとの「一意制約」カードがあります。
カード本体は開閉でき、選択したテーブルに制約があるとき（および制約を追加したとき）は自動で開き、無いときは畳まれた状態になります（ヘッダーのトグルで手動開閉も可能）。
「+」で制約を追加し、構成する列を 1 行ずつ足していきます。
制約の中の「+」で空の行が増え、その行のドロップダウンから列を選ぶと確定します（1 列ならその列が一意、複数列ならその組み合わせが一意。行の並びが宣言順です）。
ドロップダウンには同じ制約の他の行が使っていない列だけが並ぶので、同じ列を二重に選べません。
行を外すには「×」を押します。

名前を空のままにすると DDL 生成時に `UQ_{テーブル}_{列…}` が合成されます（未入力の間は、その合成名が制約名欄のプレースホルダーとして表示されます）。
名前の `.` と空白は `_` に置き換わり、前後の空白は除かれます。
DB から取り込んだ名前はそのまま保持されます。
列を削除すると、その列を含む制約は列と一緒に削除されます（残りの列だけの制約へ黙って変質させないため）。
いずれの操作も Undo できます。

キャンバス上では、制約の構成列のキー欄に `UQ` が表示されます。
1 つの列が主キー・外部キー・一意制約の構成列を兼ねることがあるため、標識は `PK` > `FK` > `UQ` の優先度で 1 つに畳んで表示します。

## リレーション

### 作成

ツールボックスの「1 対 1」「1 対 多」「多 対 多」を押すと作成モードに入り、2 つのエンティティを順にクリックすると確定します。
同じエンティティを 2 回クリックすると自己参照リレーションになります。

作成モード中はツールボックスに案内が出て、そこの「キャンセル」で中断できます。
作成モード中にツールボックスを畳むと、作成モードも一緒に中断されます（畳むと案内もキャンセルボタンも見えなくなるため）。

起点と終点が一致する既存のリレーションがある場合は重複として弾かれるので、既存のリレーションを選択して編集してください。
重複とみなされるのは向きまで一致する場合だけなので、A → B があっても B → A は作成できます。

#### 作成時の列の対応と制約名

作成時には**起点の主キー列すべて**について、列名から終点側の対応列を引き当ててペア化します。
引き当てられなかった起点列はペアに含まれないので（プロパティパネルで補えます）、同じ終点列が 2 度使われることもありません。
終点の主キー列を引き当てるのは、次のどちらかのときだけです。

- 名前が起点テーブルから導いた名前（`Orders` なら `OrderId` / `order_id`）のとき
- 起点の主キーが複数列で、起点のキー列と同じ名前（単独の `id` を除く）のとき

そのため、主キーが `(OrderId, LineNo)` の注文明細のような識別関係は `OrderId` のペアを持ち、終点の主キーにある単独の `id` が起点の `id` と対応づくことはありません（`id` はそれぞれのテーブル自身のキーなので、起点が `Projects(TenantId, Id)` なら起点の `Id` は終点の `ProjectId` と対応づきます）。
自己参照では主キー列を引き当てません。

制約名は `FK_<終点>_<起点>` 形式で自動生成されます。
テーブル名の `.` と空白は `_` に置き換わり、前後の空白は除かれます（名前の無い外部キーに DDL 生成が付ける名前と同じ規則です）。
AI チャットや MCP のツールで追加したリレーションも同じ名前になります。

### プロパティの編集

リレーションを選択すると、プロパティパネルで次を編集できます。

| 項目 | 内容 |
|---|---|
| 種別 | 1 対 1 / 1 対 多 / 多 対 多（後から変更可能） |
| 制約名 | FK 制約名 |
| キー列の対応 | 列ペアの行。1 行が「起点（参照される側）の参照先列＝主キー列と一意制約の構成列が候補」と「終点（FK を持つ側）の外部キー列」の対で、＋で行を追加・×で削除し、両側を選ぶと確定します。2 行以上なら複合外部キーで、行の並びがそのまま構成列の順序になります |
| ON DELETE / ON UPDATE | 参照アクション: NoAction / Cascade / SetNull / SetDefault |

- **多対多は中間テーブルを自動生成しません。**
  多対多の線は「中間テーブルを介する設計」を概念として表すもので、FK 列と参照アクションの指定は無効になります。
  物理設計に落とす場合は、中間テーブルを自分で追加して 1 対多 2 本で表現してください
- **リレーションは列ペアの順序付きリストを保持します。**
  複数列で構成される外部キー（複合外部キー）もそのまま表現され、取込・DDL 生成・スキーマ同期を通じて構成列が保たれます。
  ただし C# コード生成（ナビゲーションプロパティ・EF Core）が対象とするのは単一列の外部キーのみで、複合外部キーは警告つきでスキップされます

## 名前

図が持つ名前（テーブル・カラム・制約・名前付きクエリと、そのパラメータ・射影のフィールド）は 1 つの規則に従います。

- **前後の空白は除かれます**。どの経路から入れても同じです（プロパティパネル・AI のツール・取込・手で編集した図ファイル）。大文字小文字を含む綴りは、入力したままです
- **前後の空白を除いたうえで、大文字小文字を無視して一致する名前は同じ名前**です。同じ名前のテーブルを 2 つ、同じテーブルに同じ名前のカラムを 2 つ、図に置くことはできません
- **プロパティパネルは重複する名前を受け付けません**。名前は元に戻り、ステータスバーにどのテーブル（カラム）が同じ名前を持つかが出て、Undo の履歴には何も積まれません
- **名前が対象のデータベースの許す長さを超える（または保存できない文字を含む）と、ステータスバーが警告します。** 対象はテーブル・カラム・外部キー・一意制約です。
  名前は入力のまま受け付けますが、短くするまで DDL の生成と同期は断ります（[識別子の長さの上限](database.ja.md#識別子の長さの上限)を参照）

名前をデータベースの識別子と一字一句そろえる必要はありません。データベースと[同期](database.ja.md)するとき、大文字小文字だけが違うテーブル・カラムは同じ要素として扱います（同期の説明を参照）。

## 表示とナビゲーション

- **ズーム**：ステータスバーの「−」「＋」、倍率表示のクリックで 100%、「⛶」で全体表示。
  Ctrl+- / Ctrl++ / Ctrl+0 / Ctrl+Shift+0 のショートカットも使えます
- **ミニマップ**：ステータスバーのトグルで有効化します。
  図がビューポートに収まらないときに右下へ表示され、クリック / ドラッグで視点を移動できます
- **検索**：Ctrl+F でテーブル名・カラム名の部分一致検索（大文字小文字は無視）。
  Enter で次の一致へ移動、候補のクリックでジャンプ、Esc で閉じます
- **関連ハイライト**：エンティティやリレーションを選択すると、接続された要素が強調され、無関係な要素は減光します

### 表示の切り替え

ツールバーの「表示」ボタンを押すと、6 つのトグルがポップアップで開きます。
項目を切り替えても開いたままなので続けて操作でき、ポップアップの外側をクリックすると閉じます。

| トグル | キー | 効果 | 次回起動時 |
|---|---|---|---|
| ツールボックス | F9 | 左のパネルを畳む・開く | 復元する |
| プロパティパネル | F10 | 右のパネルを畳む・開く | 復元する |
| 説明表示 | — | ER 図のカラム行に説明を表示する | 復元する |
| NULL表示 | — | ER 図のカラム行に NULL 許容を表示する | 復元する |
| 簡易表示 | — | PK / FK 以外の列行を折りたたむ | 復元する |
| 全画面 | F11 | ウィンドウの枠を隠し、画面いっぱいに広げる | 復元しない |

- **パネル**：畳んだぶんキャンバスが広がり、プロパティパネルの幅をドラッグで調整していれば、隠して戻してもその幅が保たれます。
  非表示の間にエンティティを選択してもパネルは自動では開きません
- **全画面**：ツールバーとステータスバーは残るので、パネルの表示切替と組み合わせればキャンバスだけの画面になります。
  解除は F11 か「表示」グループの同じトグルです。
  タイトルバーが隠れるため、その × の代わりにツールバーの右端へ「終了」ボタンが出ます（押すとタイトルバーの × と同じく、確認なしで自動保存してから終了します）

### 自動整列

| ボタン | 動作 |
|---|---|
| 整列(格子) | 格子状に並べる。リレーション線の交差が少なくなるよう並びを探す |
| 整列(木) | ツリー状に並べる |
| 整列(自由) | 力学モデルで配置し、リレーション線が水平・垂直に近づくよう整列する |
| 幅自動 | カラム名と型が重ならない幅に調整する |

「整列(格子)」の並びの探索は、使える判定回数に上限があり、**大きな図では途中で打ち切ります**（数百テーブルの図でも待たされないため）。
打ち切りは時間ではなく判定回数で決まるので、同じ図なら何度実行しても同じ配置になります。
打ち切りが起きる規模（実測では 300 テーブルあたりから）では交差が残りやすくなるため、気になる場合は整列後に手で動かすか、「整列(木)」を試してください。

## 複数選択と一括操作

- **Ctrl+クリック**：選択をトグルします。
- **キャンバスのドラッグ**：ラバーバンド選択（矩形に交差した要素を選択）です。
- **Ctrl+A**：全エンティティを選択します（リレーションの選択は解除されます）。
- **Esc**：エンティティの選択を解除します（リレーションの選択と、作成途中のリレーション作成モードは保持されます）。

2 個以上選択すると、プロパティパネルが一括操作カードに切り替わります。

- タイトル背景色の一括変更
- 選択中すべての削除
- ドラッグによるグループ移動

いずれも 1 回の Undo で戻せます。

## Undo / Redo

Ctrl+Z / Ctrl+Y（ツールバーの「元に戻す」「やり直す」）で戻せるのは、図の内容に対する個別の編集操作です。

| 操作 | 履歴 |
|---|---|
| エンティティと列とリレーションの追加・削除・変更、移動、複製、色変更、対象 DB の切替、AI チャットによる個別の編集 | 履歴に乗り、Undo で戻せる |
| 図を丸ごと入れ替える操作（ファイル取込・DB 取込・AI による図全体の生成） | 履歴をクリアするため、Undo では戻せない |
| 選択状態、ズームやパン、ミニマップ表示といった「見え方」だけの操作 | 履歴に乗らない |

## 対象 DB の切替

ツールバー右の「対象DB:」コンボで、図のターゲット DBMS をいつでも切り替えられます。
既存の列型は新しい方言の型へ自動変換され、変換できなかった列は警告ダイアログに一覧表示されます（元の型を保持）。
切替は Undo で戻せます。
詳細は [データベース連携](database.ja.md) を参照してください。

## ファイル操作と自動保存

新規（Ctrl+N）、開く（Ctrl+O）、保存（Ctrl+S）、名前を付けて保存（Ctrl+Shift+S）。
保存形式は JSON 1 ファイルで、意味モデル（テーブル定義）と表示情報（座標・色）を分離して持つため、git での差分レビューに向きます。

ウィンドウを正常に閉じた場合は作業中の図が自動保存され、次回起動時に復元されます。
強制終了や書込失敗はこの限りではないため、区切りごとに明示的に保存しておくことをおすすめします。

開いている図のファイルが外部（MCP サーバや別プログラム）で書き換えられると、GUI がそれを検知して追従します。
未保存の変更がなければ自動で再読込し（ズーム・スクロール位置は維持）、ステータスバーに控えめな通知を出します。
未保存の変更があるときだけ、再読込するか（変更を破棄）このまま続けるかを確認します。
